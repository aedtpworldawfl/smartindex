AWFLWIKIWORLD is a lightweight, database-free, MediaWiki-style wiki engine built in plain PHP. It stores every page as a plain text file, every user as a JSON record, and every visual style as a CSS file—no database, no build step, and no external dependencies. Copy the folder onto any PHP 8.3 server (or run it on localhost), fill in one configuration file, and you have a working wiki.

Quick start

  1. Download the latest version from the GitHub Releases or the Internet Archive.
  2. Extract the folder and upload it to your PHP 8.3 server.
  3. Edit config.php.
  4. Visit $Server/index.php in your browser.

System requirements

  • PHP 8.3 or higher
  • No database (MySQL, SQLite, etc. are not required)
  • No build tools or package managers
  • No external dependencies

Installation

  1. Download the latest version of AWFLWIKIWORLD from the GitHub Releases or the Internet Archive.
  2. Extract the downloaded folder and upload it to the web root of your PHP 8.3 server (or place it on localhost).
  3. Open config.php in a text editor—this is the only file you need to touch by hand to get a working wiki.
  4. Set $Server to the exact base URL you will use to reach the wiki. For example:
  5. * $Server = "https://example.com/wiki";
  6. * For local testing: $Server = "http://localhost:8099";
  7. Set $Sitename, $MetaTitle, and $MetaDescription to describe your wiki.
  8. Set $Username and $Password to your admin login.
  9. Choose a $route mode.
  10. Visit $Server/index.php in a browser. You should see the built-in Main Page.

$route modes

$route controls the shape of every page's URL:

  • "0" — {$Server}/index.php?title=Pagename (and ?title=Space/Pagename). Works everywhere, no server configuration needed. This is the default.
  • "1" — {$Server}/Pagename (and {$Server}/Space/Pagename). Pretty URLs. Requires the supplied .htaccess and an Apache server with mod_rewrite and AllowOverride All.
  • "2" — {$Server}/namespaces/Pagename. Looks like a direct link into the namespaces/ folder, but is still served by index.php—the .htaccess rules stop anyone from downloading the raw .txt file directly.

Configuration

AWFLWIKIWORLD is designed to be minimalist. You only need to fill in one configuration file (config.php) to get the entire wiki running. The core settings include:

  • Site Name: The name of your wiki
  • Admin Account: The initial administrator's username and password
  • File Storage Path: Where pages, users, and style files are stored
  • Base URL: The access address for the wiki

Usage guide

As a visitor

Anyone can:

  • Read any page.
  • Use the search box in the header: type, and a dropdown offers up to five matching pages, each with its first image — click one to open it. Press Enter to jump straight to a title, or use Special:Search for full results.
  • Browse AllPages to see every page that exists.
  • Browse Special:Missing to see every red link — pages that are linked to but don't exist yet — and click one to create it.
  • Browse the image gallery at allimages/index.php—see every uploaded picture and use the Copy link / Copy name buttons on any image.
  • Browse the account directory at allusers/index.php.
  • Download any page as a .txt file (the raw AWFLWIKITEXT) or as a self-contained .html file.
  • Print any page (which also lets you "print to PDF" from the browser's print dialog).

Visitors cannot create pages, edit pages, or upload images—those require an account.

As a registered user

Creating an account: Go to Special:Register and fill in a username, display name, email, password, and a security question and answer. Usernames must be 3–32 characters and the name admin is reserved. Once registered, log in at Special:Login.

Recovering a forgotten password: Open users/recover.php. You will be asked for your username, then your registration email and your security answer. If everything matches, you are immediately allowed to set a brand-new password—no email link required. Passwords and security answers are never stored in plain text; only their hashes are kept.

Creating and editing pages: To create a page, search for or navigate to its title and click Create. To edit an existing page, click Edit. Both open the same editor with a toolbar, a source editor, and a visual editor (preview) tab. Click Save page to publish your changes immediately. If an admin has protected a page, only an admin can edit it.

AWFLWIKITEXT markup

AWFLWIKITEXT is a small, MediaWiki-inspired markup language. All of it can be typed by hand or inserted with the editor toolbar. See AWFLWIKIWORLD/AWFLWIKITEXT for the full reference. Key syntax includes:

  • Bold: text
  • Italic: text
  • Underline: text
  • Strikethrough: text
  • Inline code: ` text `
  • Superscript: text
  • Subscript: text
  • Highlight: text
  • Headings: = Heading = through ====== Heading ======
  • Bulleted list: * item
  • Numbered list: # item
  • Blockquote: > quote
  • Horizontal rule: ----
  • Code block: 
     code
  • Internal link: Page Name or label
  • External link: label
  • Bare image: a filename or URL ending in .jpg, .jpeg, .png, .gif, .svg, or .webp, on its own line
  • Infobox:
    ...
    ...
    FieldValue
  • Escape/raw text: wrap in ...

Infoboxes

An infobox is a small fact-table, usually shown floated at the top right of an article. Write one like this:

<infobox> |title=Subject Name| |image=example.jpg| |caption=A short caption| |Born=1 January 2000| |Occupation=Example, Example| </infobox>

Rules: title, image, and caption are each allowed only once per infobox, and always appear in that fixed order. Every other line becomes its own row: the part before the equals sign is shown in bold as the row's label, and the part after it is the value.

Uploading images

If the admin has enabled uploads, any logged-in user can add a picture at Special:Upload. Only .jpg and .png files are accepted. Once uploaded, an image can be referenced in any page just by its filename.

Downloading and printing

Every page offers:

  • Download .txt — the raw AWFLWIKITEXT, exactly as stored.
  • Download .html — a single, self-contained HTML file with the page's styling embedded in it, so it looks right even with no internet connection.
  • Print / PDF — opens your browser's print dialog, which on most browsers can also "print" straight to a PDF file.

As the administrator

Log in with the $Username / $Password set in config.php. The admin account is not a row in users/users.json—it is defined directly in the configuration file and always has full control.

The Dashboard: Open the Dashboard link in the navigation bar (dashboard/index.php). It has four sections:

  • Skins — pick which skin is active site-wide, or create a brand-new skin by typing its CSS. The default vector2022 skin can be selected but never edited or deleted.
  • Colors — a small palette for the site's core colors (header background, header text, buttons, button text, wiki page text, and links). Pick a color visually or type a hex code directly.

Architecture

AWFLWIKIWORLD's architecture is extremely simple, storing all data as files:

  • Page content — plain text files (.txt). One file per page, directly editable with any text editor.
  • User records — JSON files. One JSON file per user, containing username, password hash, permissions, etc.
  • Visual styles — CSS files. One CSS file per skin, freely customizable.

This design gives AWFLWIKIWORLD the following advantages:

  • Zero database maintenance: No database to install, configure, or back up.
  • Minimal deployment: Copy the folder and run.
  • Portability: The entire wiki can be migrated or backed up by copying files.
  • Directly editable: All content can be modified with any text editor.

File structure

The engine is a small number of PHP scripts working together:

  • index.php — The interface every visitor loads.
  • config.php — Site settings.
  • .htaccess — Hides raw data files (.txt, .json) from being downloaded directly, and enables pretty URLs.
  • includes/header.php, includes/footer.php, includes/functions.php — Shared page frame and engine code.
  • users/users.json — Every registered account (hashed passwords only).
  • users/recover.php — The "forgot password" page.
  • assets/site.css, assets/site.js, assets/search.js — The default look, the editor toolbar script, and the header search dropdown script.
  • skins/vector2022.css — The default skin. More skins can be added here.
  • images/ — Uploaded .jpg / .png files. images/trash/ holds images an admin has deleted but not yet permanently removed.
  • allusers/index.php — Public list of accounts.
  • allimages/index.php — Public gallery of uploaded images.
  • namespaces/{pagename}.txt — A root-level article.
  • namespaces/{space name}/{pagename}.txt — An article inside a named space.
  • dashboard/index.php — The admin panel (skins, colors, pages, images).
  • dashboard/history.json, dashboard/history.php — The admin's own edit history.
  • dashboard/protected.json — The list of protected page titles.
  • sitemap/sitemap.xml, sitemap/sitemap.php — The generated sitemap and the script that builds it.
